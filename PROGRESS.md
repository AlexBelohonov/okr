## Product Decisions

PostgreSQL; full OKR product rather than an HR suite; multi-org memberships; fixed owner/admin/manager/member/viewer roles; teams and designated managers; all active members see objectives; multiple alignment parents and separate prerequisite DAG; per-objective key-result or weighted-child scoring; prerequisites warn, with an explicit completion override; one lead plus co-owners/contributors/followers; Docker Compose; chapter-by-chapter reviews.

Accounts use SMTP verification/recovery or self-hosted copied links. Passwords require 12-128 characters. Profile edits change names, not email. Invitation possession verifies the bound email; reset possession does not. Existing memberships cannot be promoted/reactivated by accepting invitations. Copied global resets retain trusted host-operator Docker/DB access; ordinary tenant admins cannot issue them through HTTP.

Owners control owner-role changes and transfer. Transfer makes its initiator an admin and preserves other owners. Only owners/admins appoint/remove designated managers; designations require manager/admin/owner roles. Suspension/viewer demotion requires reassignment of all lead/editing-assignment/metric-owner references, including archived work, and clears management designations when appropriate. Historical authorship and other-organization access remain intact. Browser-tab organization selection never grants API access.

Members create their own personal objectives or work for teams they belong to; managers/admins create company objectives. Leads/co-owners/designated team managers/admins edit structure; contributors and metric owners update values. Closed/archived ownership reassignment preserves metrics/frozen score/closing note. Structure/numeric changes require reopen/unarchive. Archive preserves history; removed metrics retain audit snapshots. Selected period dates contain objective dates; used period dates/deletion are guarded. Date filters use inclusive overlap. Overview counts unique unarchived objectives, with active averages/overdue dates in the organization timezone. Metric writes require and advance both metric/objective versions.

R006 supersedes R005's child-mode draft restriction. Direct active/completed, unarchived children contribute by parent-specific positive weights. Draft/cancelled/archived children are excluded from numerator and denominator; empty inputs score zero. Key results and child inputs never combine. Completed scores freeze until reopen; shared children count once per parent and each organization objective counts once.

Alignment mutations need live/unarchived endpoints and edit rights on both. Dependency mutations need a live dependent editor and tenant-visible prerequisite (closed/archived prerequisites allowed). Both endpoint versions are required. Each graph independently rejects self/duplicate/foreign/cyclic links. Dependency weights are 1 and never affect progress. A prerequisite resolves only when completed; unfinished archived/cancelled work remains a warning. Completion requires a separate nonblank override note if direct prerequisites remain unresolved. The closing record/audit retain the note and prerequisite-state snapshot; reopen clears the current record but preserves immutable history.
